# 화면 구현

코드 규칙, 화면 ID와 경로, API·상태 규칙은 루트 AGENTS.md를 따릅니다. 이 스킬은 화면 하나를 만드는 순서와 완료 기준만 다룹니다. 이슈·브랜치·PR 절차는 `issue-to-pr` 스킬을 함께 사용합니다.

## 1. 시작 전 확인

- AGENTS.md의 "화면과 경로" 표에서 화면 ID, 경로, 담당 이슈를 확인합니다. 표에 없는 화면은 만들지 않고 사용자에게 묻습니다.
- 같은 폴더의 `screens.md`에서 이 화면의 연결, 상태, 활성 조건, 예외 트리거를 확인합니다.
- Figma 모바일 화면에서 해당 ID의 프레임을 확인합니다. 글자 크기 변형(크게·더 크게)이 있는 화면은 함께 봅니다.
- 이 화면에서 이동하는 화면과 들어오는 화면을 정리합니다. 대상 경로가 아직 없으면 버튼을 비활성으로 두거나 숨기고, 404 경로로 연결하지 않습니다.
- API가 필요한 화면이면 Notion API 목록에서 요청·응답 형식을 확인합니다. 형식이 없으면 같은 형태의 가짜 데이터로 만들고 PR에 연결 보류를 적습니다.

## 2. 구현 순서

1. src/pages/[pageName]/[PageName]Page.tsx를 만들고 src/App.tsx의 AppShell children에 경로를 추가합니다.
2. 화면 안에 자체 119 버튼이 있으면 AppShell의 `hiddenEmergencyBarPaths`에 경로를 추가합니다.
3. src/components/ui.tsx와 ScreenElements.tsx의 공통 컴포넌트로 먼저 구성합니다. 여러 화면에서 쓰는 요소만 src/components에, 이 화면 전용은 src/pages/[pageName]/components에 둡니다.
4. 데이터는 `useAppStore()` 상태나 src/api 함수에서 받습니다. 화면 검토용 가짜 데이터는 페이지 폴더의 `sample*.ts`에 두고 주석으로 교체 대상 이슈를 적습니다.
5. 로딩, 오류, 빈 상태를 디자인에 있는 화면(S05c, S05d, S06a 등)이나 화면 안 상태로 처리합니다.
6. 값 변환·계산 로직은 순수 함수로 분리하고 `*.test.ts`를 작성합니다.

## 3. 완료 기준

- [ ] 390px 폭에서 가로 넘침이 없습니다.
- [ ] 글자 크기 보통·크게·더 크게(18/22/26px)에서 넘침, 잘림, 겹침이 없습니다.
- [ ] 터치 영역이 모두 44px 이상이고, 주요 버튼은 58px 이상입니다.
- [ ] 본문 글자가 16px 이상이고, 색은 theme.css 토큰만 사용합니다.
- [ ] `h1`이 하나 있고, 키보드 Tab으로 모든 버튼과 링크에 도달할 수 있습니다.
- [ ] 119 바가 화면 규칙대로 보이거나 숨겨집니다.
- [ ] 디자인에 없는 문구를 추가하지 않았고, 저장 위치를 단정하는 문구가 없습니다.
- [ ] 768px 이상에서 480px 앱 영역 안에 올바르게 표시됩니다.
- [ ] `npm run format`, `npm run lint`, `npm run typecheck`, `npm run test`, `npm run build`가 통과합니다.

## 4. PR에 남길 내용

- 가짜 데이터나 비활성 버튼처럼 연결을 보류한 부분과 이유 (`Refs #이슈`)
- 글자 크기 3단계 화면 캡처
